# make_weights.py — сборка весов автоопределения языка сниппетов

`make_weights.py` — Python-скрипт (один файл, только стандартная библиотека),
аналог консольного тренера `LangNBTrainer.exe`. Он обучает наивную Байес
модель на **ваших личных коллекциях скриптов** и сохраняет файл весов
`scripts_weights.bin`, который понимает SSH Snippets Keeper.

Результат полностью совместим с приложением: формат байт-в-байт совпадает
с форматом Delphi-тренера, поэтому веса можно собирать любым из двух способов.

---

## Требования

- Python **3.8+** (проверено на 3.14). Сторонних пакетов не требуется.
- Windows (кодировка ANSI по умолчанию — cp1251/cp1252; на других ОС
  тоже работает, ANSI-фоллбэк берётся из локали).

## Использование

```
python make_weights.py <bash_папка> <cmd_папка> <powershell_папка> [-o ФАЙЛ] [--prune N]
python make_weights.py --inspect <scripts_weights.bin>
```

Пример:

```
python make_weights.py C:\MyCorpus\bash C:\MyCorpus\cmd C:\MyCorpus\powershell -o scripts_weights.bin
```

| Параметр | Описание |
|---|---|
| `<bash_папка> <cmd_папка> <powershell_папка>` | Три папки с коллекциями скриптов (ровно три, в этом порядке). Обход рекурсивный. |
| `-o, --output` | Куда сохранить веса. По умолчанию `scripts_weights.bin` в текущей папке. |
| `--prune N` | Порог чистки словарей: слова с суммарным числом вхождений меньше N удаляются. По умолчанию **3**. Для маленьких выборок (до ~30 файлов на язык) ставьте `--prune 1`. |
| `--inspect ФАЙЛ` | Не обучать, а показать содержимое готового файла весов (документы, словарь, топ-слова). |

После сохранения скрипт **самопроверяется**: перечитывает файл и сверяет
все словари — в конце печатает `Самопроверка файла: OK`.

## Структура папок на компьютере

Имена папок — любые, порядок аргументов задаёт язык. Удобно так:

```
C:\MyCorpus\
    bash_scripts\        ← .sh / .bash
    cmd_scripts\         ← .bat / .cmd
    powershell_scripts\  ← .ps1 / .psm1
```

- Обход **рекурсивный**: подпапки обрабатываются автоматически
  (например, `bash_scripts\cron\`, `bash_scripts\docker\`).
- Расширения фильтруются автоматически (см. таблицу выше). Если по
  расширениям в папке не нашлось ничего, но файлы есть — скрипт возьмёт
  **все** файлы и напечатает предупреждение (почти всегда это перепутанный
  порядок аргументов).
- Кодировка файлов любая: UTF-8 (с BOM и без), UTF-16, ANSI —
  определяется автоматически.

## Сколько нужно файлов

| Объём выборки | Эффект |
|---|---|
| **50–300 файлов на язык** | Идеально. Чем больше и разнообразнее — тем точнее определение, особенно на коротких однострочниках. |
| 20–50 файлов на язык | Рабочий минимум (в репозитории проекта именно 30 на язык). |
| < 15–20 на язык | Определение будет часто «сдаваться» и возвращать bash по умолчанию. |

Скрипты берите **типичные и рабочие**: реальные операционные скрипты —
деплой, мониторинг, парсинг логов, работа с реестром/сервисами и т.п.
Разнообразие конструкций (циклы, функции, пайпы) важнее объёма.

## Правила качества выборки

1. **Не подмешивайте чужие языки**: в папку cmd — только bat/cmd, и т.д.
   Один файл не того языка портит профиль целого класса.
2. **Обёртки исключаются автоматически**: cmd/bash-файлы, вызывающие
   `powershell`/`pwsh`, пропускаются (счётчик `skipped(wrapper)`), иначе
   токены PowerShell загрязнят профиль cmd. В PowerShell-выборку
   обёртки класть можно.
3. Комментарии в реальных скриптах **не мешают** — классификатор учится на
   частотности токенов; просто не пишите учебные файлы из одних комментариев.
4. Файлы с ошибками/мусором (дампы, экспорты переписок) лучше не включать.

## Куда положить результат

Файл `scripts_weights.bin` кладётся **рядом с exe** приложения
(`SSHSnippetsKeeper.exe`). При запуске из исходников достаточно положить
его в `Assets\ExeData\` — приложение найдёт веса по тому же правилу,
что и остальные файлы данных.

Веса читаются **один раз при старте** — после замены файла перезапустите
приложение. Если файла нет или он повреждён, приложение молча работает
на встроенном эвристическом определителе.

## Как это работает (кратко)

Токенизатор режет текст на слова (включая приклеенные `-`/`$`: `get-process`,
`$var`) и операторные последовательности (`|`, `&&`, `>>`, `>&` из `2>&1`).
Для каждого языка накапливаются: сколько раз встретилось слово (TF) и в
скольких документах (DF). При определении: счёт языка = Σ IDF-взвешенных
лог-вероятностей его токенов (сглаживание Лапласа, без априорных
вероятностей — размер выборки не влияет). Порог уверенности: слабое
доказательство или малый отрыв от второго места → язык по умолчанию (bash).

## Проверка результата

```
python make_weights.py --inspect scripts_weights.bin
```

покажет по каждому языку: число документов, размер словаря, топ-слова.
Здоровый файл: у каждого языка docs > 0, словарь от ~150–300 слов
(при prune=3 на выборке 30+ файлов) и осмысленные топ-слова
(`echo`/`set` для bat, `get-`/`write-output` для powershell и т.п.).
