# SSH Snippets Keeper

Менеджер сниппетов SSH-команд для Windows с автоматизацией ввода в терминале, макросами, генератором паролей и набором сетевых утилит. Приложение хранит библиотеку команд в локальной базе SQLite, подставляет их в любое подключённое окно терминала (MobaXterm, Xshell, PuTTY, Tabby, KiTTY, SecureCRT) посимвольным вводом и умеет запрашивать недостающие параметры прямо перед выполнением.

Написан на Delphi (Win32, VCL). Интерфейс — русский и английский (переключается на лету), горячие клавиши полностью переназначаемые.

## Возможности

**Библиотека команд**

- Сниппеты с категориями, тегами, избранным и рабочими пространствами (workspaces);
- Дерево категорий с поиском, список сниппетов с фильтрацией;
- Поиск с языком запросов: фильтры по тегам, категориям, названию и комментарию, только избранное, исключения (см. [Поиск по сниппетам](#поиск-по-сниппетам));
- Редактор сниппетов с подсветкой bash-синтаксиса (SynEdit + кастомный highlighter);
- Автодополнение bash-команд и аргументов (база команд подгружается из текстовых файлов и пополняется пользователем).

**Выполнение в терминале**

- Запуск сниппета в указанное окно терминала: активация окна, установка фокуса, посимвольный ввод с настраиваемыми задержками;
- Белые списки приложений и окон (по классу окна) — макросы не будут отправлены в чужое окно;
- Синтаксис макросов: паузы, Enter, отправка виртуальных клавиш, интерактивный запрос параметров (строка, число, hex, float, пароль, дата, подтверждение);
- Мастер быстрого поиска (HUD) по глобальной горячей клавише — выполнить команду, не открывая главное окно.

**Генератор паролей**

- Типы: PIN, hex-токен, MAC-адрес, UUID v4, пароль по политике Active Directory, произвольный (с включением/исключением символов);
- Оценка энтропии, история генераций, генерация bcrypt-хэша.

**Сетевые утилиты**

- Конвертер Epoch/Unix-времени (секунды/миллисекунды/микросекунды, ISO 8601, Apache, syslog, извлечение меток времени из текста);
- Генератор cron-выражений;
- IP-калькулятор: разбиение сетей (VLSM), адреса, маски;
- Калькулятор chmod/chown с пресетами и историей;
- Умный конструктор архивов (Archive Builder).

**Синхронизация и обмен**

- Двусторонняя синхронизация базы сниппетов с локальной папкой в формате Markdown (экспорт и импорт).

**AI-ассистент**

- Облачные провайдеры (готовые пресеты Yandex AI Studio: LLM и Agents — YandexGPT, DeepSeek и др.) для генерации команд по текстовому описанию;
- Полностью локальный режим: LLM через llama-cpp-python на GGUF-модели, Python подключается из встраиваемого дистрибутива — данные не покидают машину.

**Безопасность**

- Сканер секретов: перед сохранением сниппет проверяется regex-паттернами и энтропийным анализом (API-ключи, токены, приватные ключи);
- Контроль конфликтов горячих клавиш внутри формы.

**Прочее**

- Полностью переназначаемые горячие клавиши с валидацией конфликтов;
- Локализация ru/en на лету (JSON-словари);
- Защита от повторного запуска (один экземпляр приложения);
- FastMM5 и отчёт об утечках памяти в Debug-сборке.

## Архитектура и структура репозитория

Приложение построено послойно: формы не знают о базе данных напрямую — доступ идёт через сервисы и интерфейсы, зависимости собираются в `Core.AppContext` при старте.

```
SSHSnippetsKeeper/
├── Automation/            # Автоматизация ввода: WindowHelper, WindowMonitor, ProcessProfile
├── Assets/
│   ├── ExeData/           # Ресурсы рядом с exe: настройки, локализация, автодополнение
│   │   └── Python/        # (не в git) встраиваемый Python 3.13 для локального AI
│   └── Images/            # Иконки и графика
├── Common/                # Общие модули: константы, хелперы, локализация, настройки
├── Core/
│   ├── Entities/          # Доменные модели: Snippet, Category, Tag, User
│   ├── Services/          # Бизнес-логика: SnippetService, HotkeyService, PasswordService...
│   ├── Interfaces/…       # Контракты (Core.Interfaces.*)
│   └── …                  # AppContext, LocalAIService, Markdown-импорт/экспорт
├── Database/
│   ├── Schema/            # SQL-схема и seed-данные (компилируются в ресурс)
│   └── Tests/             # SQL-скрипты проверки данных
├── Data/
│   ├── Repositories/      # Репозитории поверх FireDAC
│   └── Data.Database.pas  # TDataModule: подключение, PRAGMA, накат схемы
├── MacroEngine/           # Разбор и выполнение макросов, типы ввода
├── Resources/             # Ресурсы приложения (иконка)
├── Tests/                 # DUnitX-тесты (консольный раннер)
├── ThirdParty/            # Bcrypt, JSONSerializer, ArrayHelper
└── UI/
    ├── Controls/          # Кастомные контролы (адаптер темы SynEdit и др.)
    ├── Controllers/       # Контроллеры: поиск, дерево категорий, синхронизация, запуск сниппетов
    ├── Forms/             # VCL-формы
    ├── Helpers/           # UI-хелперы
    ├── Services/          # UI-сервисы: состояние приложения, AI-сервис, сообщения
    └── ViewModels/        # Модели представления
```

Ключевые принципы:

- интерфейсы сервисов собраны в `Core/Core.Interfaces.*.pas`, реализации — в `Core/Services` и `UI/Services`;
- репозитории (`Data/Repositories`) инкапсулируют SQL; схема БД хранится отдельными `.sql`-файлами;
- именование юнитов — точечное: `Common.*`, `Core.*`, `Data.*`, `UI.Services.*`, `Tests.*`.

### Встраиваемый Python (опционально, для локального AI)

Основное приложение собирается и работает без Python. Локальная LLM требует:

1. Скачайте **Windows embeddable package** Python 3.13 (32-bit) с [python.org](https://www.python.org/downloads/windows/) и распакуйте в `Assets\ExeData\Python\` (папка исключена из git через `.gitignore`);
2. Модуль `llama-cpp-python` устанавливается из интерфейса настроек AI (кнопка установки модуля), GGUF-модель указывается там же.

Без встроенного Python приложение попробует найти системный Python через реестр (Python4Delphi).

## Первый запуск

Приложение ищет файлы ресурсов в двух местах: сначала рядом с `.exe` (релизный сценарий), затем в `<корень репозитория>\Assets\ExeData\` (сценарий разработки). Если файл не найден, папка создаётся автоматически.

| Файл | Назначение |
|---|---|
| `settings.json` | Пользовательские настройки (создаётся из `settings.template.json`; в git не попадает) |
| `Translation\ui-texts.ru.json`, `ui-texts.en.json` | Локализация |
| `bash-autocomplete.txt`, `extra-commands.json` | База автодополнения bash |
| `Python\` | Встраиваемый Python (см. выше) |
| `Styles\` | VCL-стили интерфейса (.vsf); без них доступен только стандартный стиль Windows |

Стили интерфейса в репозиторий не входят (лицензия RAD Studio). Чтобы переключать темы в *Настройки → Общие*, положите `.vsf`-файлы (например, из `C:\Users\Public\Documents\Embarcadero\Studio\23.0\Styles\`) в папку `Styles` рядом с `.exe` (папки в git не попадают). Стиль применяется сразу и запоминается в `settings.json`; TSynEdit-редакторы перекрашиваются автоматически.

Порядок первого запуска:

1. Скопируйте `Assets\ExeData\settings.template.json` в `settings.json` (рядом с exe) и при необходимости заполните секции `AllowedWindows`, `AllowedApplications` и пресеты AI;
2. Запустите приложение, создайте базу данных — **Ctrl+N** (схема накатывается автоматически из встроенного ресурса);
3. Откройте базу — **Ctrl+O**, закройте — **Ctrl+Q**.

## Синтаксис макросов

Макросы пишутся прямо в тексте сниппета в фигурных скобках. Нераспознанная конструкция остаётся обычным текстом.

| Макрос | Действие |
|---|---|
| `{SLEEP 500}` | Пауза 500 мс |
| `{ENTER}` | Нажатие Enter |
| `{SENDKEY 13}` | Отправка виртуальной клавиши (VK-код) |
| `{INPUT подсказка}` | Запрос ввода строки перед выполнением |
| `{INPUT [ТИП:значение] подсказка}` | Запрос ввода заданного типа со значением по умолчанию |

Типы ввода: `STRING`, `NUMBER`, `HEX`, `FLOAT`, `PASSWORD`, `DATE`, `CONFIRM`.

Пример сниппета — перезапуск nginx на указанном сервере:

```
ssh {INPUT [STRING:user@host] Адрес (user@host)}
{ENTER}
{SLEEP 800}
sudo systemctl restart nginx
{ENTER}
```

Перед выполнением приложение запросит адрес, подключится к выбранному окну терминала, наберёт команду посимвольно и подтвердит Enter. Разбор макросов кэшируется (до 5000 сниппетов).

## Поиск по сниппетам

Строка поиска в главном окне и в HUD быстрого поиска понимает простой язык запросов. Поиск нечувствителен к регистру. В полнотекстовом режиме (FTS5, триграммный индекс) обычные слова находят и части слов: запрос `List` найдёт `TList`; индекс покрывает название, код, комментарий и теги, результаты сортируются по релевантности.

| Токен | Действие |
|---|---|
| `слово` | Полнотекстовый поиск по названию, коду, комментарию и тегам; несколько слов подряд ищутся как фраза |
| `tag:nginx` | Имя тега содержит подстроку; несколько `tag:` - все условия должны выполняться одновременно |
| `cat:сеть` | Сниппет находится непосредственно в подходящей категории (вложенные категории не учитываются); несколько `cat:` - достаточно любой |
| `title:ssh` | Подстрока в названии; несколько `title:` - все должны совпасть |
| `comment:туннель` | Подстрока в комментарии; несколько `comment:` - все должны совпасть |
| `fav` | Только избранные сниппеты |
| `-слово` | Исключить сниппеты, содержащие слово в тексте (название, код; в FTS-режиме также комментарий и теги) |

Токены свободно комбинируются: `fav tag:docker title:logs -prod` - избранные сниппеты с подходящим тегом, `logs` в названии и без `prod`. Неизвестные префиксы (например, `foo:bar`) считаются обычными словами поиска. В режиме без FTS обычные слова и исключения ищутся подстрокой по названию и коду.

Разбор запроса: `Common/QueryLanguage.pas`, SQL-построитель: `Data/Repositories/SnippetRepository.pas` (`SearchAdvanced`), тесты: `Tests/Tests.QueryLanguage.pas`.

## Горячие клавиши по умолчанию

Глобальные (работают из любого окна приложения): **Alt+Q** — быстрый поиск (HUD), **Ctrl+Alt+G** — генератор паролей. Переназначаются в настройках.

Главное окно:

| Клавиши | Действие |
|---|---|
| Ctrl+Alt+A / D / E | Добавить / удалить / редактировать сниппет |
| Alt+A / D / E | Добавить / удалить / редактировать категорию |
| Ctrl+Shift+A / D / E | Добавить / удалить / редактировать тег |
| Ctrl+N / Ctrl+O / Ctrl+Q | Создать / открыть / закрыть базу данных |
| Ctrl+Alt+Shift+E | Синхронизация с папкой (Markdown) |
| Ctrl+Shift+S | Быстрый поиск |
| Ctrl+Shift+G | Генератор паролей |
| Ctrl+Shift+C | Генератор cron |
| Ctrl+Shift+T | Конвертер Epoch |
| Ctrl+Shift+I | IP-калькулятор |
| Ctrl+Shift+M | Калькулятор chmod |
| Ctrl+Shift+Z | Конструктор архивов |
| Ctrl+Alt+P | Настройки |

Форма добавления/редактирования сниппета: **Ctrl+I** — AI-ассистент, **Ctrl+Alt+P** — конфигурация AI.

Форма настроек AI: **Ctrl+S** — сохранить, **Ctrl+N/E/D** — создать/изменить/удалить провайдера, **Ctrl+Shift+N/E/D** — создать/изменить/удалить модель.

Редактор тегов и менеджер рабочих пространств: **Ctrl+A** / **Ctrl+E** / **Ctrl+D** — добавить / изменить / удалить.

Все комбинации переназначаются в настройках; при выборе занятого сочетания внутри одной формы выводится конфликт.

## База данных

- Движок: SQLite через FireDAC, файл базы выбирает пользователь;
- Схема хранится в `Database/Schema/000_schema_init.sql`, при сборке компилируется в ресурс `000_schema_init.res` и применяется при создании новой базы (`{$R}`-директива в `.dpr`);
- Seed-данные: `000_seed_data.sql`, `000_seed_data_full.sql`; проверка целостности: `Database/Tests/verify_data.sql`;
- Сущности: сниппеты, категории, теги, пользователи; связи многие-ко-многим;
- После открытия базы применяются PRAGMA (WAL и т. п.), при закрытии — принудительный сброс на диск.

## Синхронизация с Markdown-папкой

Двусторонняя синхронизация выгружает сниппеты в локальную папку в виде Markdown-файлов и подтягивает изменения обратно (**Ctrl+Alt+Shift+E**). Импорт/экспорт реализован в `Core.MarkdownExporter` и `Core.MarkdownImporter`, оркестрация — `UI/Controllers/SyncController`.

## AI-ассистент

Два режима, конфигурация — в форме настроек AI:

- **Облачные провайдеры** — наборы хабов и моделей (пресеты Yandex AI Studio: YandexGPT 5 Lite, DeepSeek V4 Flash, Alice AI, режим Agents). API-ключи хранятся локально в `settings.json` и в git не попадают. Ассистент генерирует команды по текстовому запросу и очищает ответ от разметки перед вставкой в сниппет;
- **Локальная модель** — llama-cpp-python c GGUF-моделью на встраиваемом Python (см. [Сборка](#сборка-из-исходников)). Полностью офлайн.

## Локализация

Словари — JSON-файлы в `Assets/ExeData/Translation/`:

- `ui-texts-master.json` — эталонный набор ключей;
- `ui-texts.ru.json`, `ui-texts.en.json` — языковые словари.

Ключи иерархические, например `Actions.MainForm.Data.AddSnippet`. Язык выбирается в настройках и переключается без перезапуска (`LanguageMenuController`). Новый язык добавляется копированием master-файла и переводом значений.

Тексты из кода (диалоги, ошибки, подсказки) живут в ветке `Messages` и берутся через `TUIStateLoader.GetMessage('Common.Confirmation')` — без префикса `Messages`. Поддерживается подстановка аргументов: `GetMessage('Markdown.DeleteFileError', [FileName])`. Заголовки форм и компоненты переводятся автоматически (`TUIStateLoader.ApplyTranslations`) для всех наследников `TBaseFormUI`; остальные формы вызывают метод явно.

## Соглашения по коду и коммитам

- Именование юнитов — точечное: `Common.*`, `Core.*`, `Data.*`, `UI.Services.*`, `Tests.*`; вендорский код в `ThirdParty` не переименовывается;
- Исходники — UTF-8 с BOM; пользовательские тексты (сообщения, заголовки, подсказки) — только через словарь локализации, литералов с кириллицей в коде нет;
- Слои: формы → контроллеры/сервисы → интерфейсы (`Core.Interfaces.*`) → репозитории → SQLite;
- Коммиты — conventional-префиксы (`feat:`, `fix:`, `refactor:`, `docs:`) с описанием на русском: `feat: Внедрение генерации Bcrypt в генераторе паролей`;
- Отладка — FastMM5 с отчётом об утечках (`ReportMemoryLeaksOnShutdown` в Debug).
