# SSH Snippets Keeper

Менеджер сниппетов SSH-команд для Windows с автоматизацией ввода в терминале, макросами, генератором паролей и набором сетевых утилит. Приложение хранит библиотеку команд в локальной базе SQLite, подставляет их в любое подключённое окно терминала (MobaXterm, Xshell, PuTTY, Tabby, KiTTY, SecureCRT) посимвольным вводом и умеет запрашивать недостающие параметры прямо перед выполнением.

Написан на Delphi (Win32/Win64, VCL). Интерфейс — русский и английский (переключается на лету), горячие клавиши полностью переназначаемые.

## Возможности

**Библиотека команд**

- Сниппеты с категориями, тегами, избранным и рабочими пространствами (workspaces);
- Дерево категорий с поиском, список сниппетов с фильтрацией;
- Поиск с языком запросов: фильтры по тегам, категориям, названию и комментарию, только избранное, исключения (см. [Поиск по сниппетам](#поиск-по-сниппетам));
- Редактор сниппетов с подсветкой bash-синтаксиса (SynEdit + кастомный highlighter);
- Автодополнение bash-команд и аргументов (база команд подгружается из текстовых файлов и пополняется пользователем).

**Выполнение в терминале**

- Запуск сниппета в указанное окно терминала: активация окна, установка фокуса, посимвольный ввод с настраиваемыми задержками;
- Белые списки приложений и окон — макросы не будут отправлены в чужое окно: для каждого разрешённого приложения можно ограничить классы окон (PuTTY, CMoTTY, …) и заголовки (regex);
- Синтаксис макросов: паузы, Enter, отправка виртуальных клавиш, интерактивный запрос параметров (строка, число, hex, float, пароль, дата, подтверждение);
- Мастер быстрого поиска (HUD) по глобальной горячей клавише — выполнить команду, не открывая главное окно.

**Цепочки и массовые операции**

- Цепочки: именованные последовательности сниппетов с паузой после каждого шага, пошаговый ввод в выбранное окно с панелью прогресса (Стоп / Esc);
- Мультивыбор в списке сниппетов: выполнить по порядку, плоский экспорт в Markdown-папку, массовое добавление/удаление тегов, перенос в категорию — в том числе другого пространства, с сохранением избранного.

**Генератор паролей**

- Типы: PIN, hex-токен, MAC-адрес, UUID v4, пароль по политике Active Directory, произвольный (с включением/исключением символов);
- Оценка энтропии, история генераций, генерация bcrypt-хэша.

**Сетевые утилиты**

- Конвертер Epoch/Unix-времени (секунды/миллисекунды/микросекунды, ISO 8601, Apache, syslog, извлечение меток времени из текста);
- Генератор cron-выражений;
- IP-калькулятор: разбиение сетей (VLSM), адреса, маски;
- Калькулятор chmod/chown с пресетами и историей;
- Умный конструктор архивов (Archive Builder).

**Синхронизация и обмен**

- Двусторонняя синхронизация базы сниппетов с локальной папкой в формате Markdown (экспорт и импорт).

**AI-ассистент**

- Облачные провайдеры (готовые пресеты Yandex AI Studio: LLM и Agents — YandexGPT, DeepSeek и др.) для генерации команд по текстовому описанию;
- Полностью локальный режим: LLM через llama-cpp-python на GGUF-модели, Python подключается из встраиваемого дистрибутива — данные не покидают машину.

**Безопасность**

- Сканер секретов: перед сохранением сниппет проверяется regex-паттернами и энтропийным анализом (API-ключи, токены, приватные ключи);
- Шифрование базы данных сниппетов (SQLite3 Multiple Ciphers): ключ привязывается к машине (DPAPI) или выводится из парольной фразы; экспорт/импорт ключа для переноса базы между машинами (см. [Шифрование базы данных](#шифрование-базы-данных));
- API-ключи AI и черновики редактора шифруются DPAPI с привязкой к пользователю Windows: скопированный на другую машину или в другой профиль `settings.json` ключи не раскрывает;
- Контроль конфликтов горячих клавиш внутри формы.

**Прочее**

- Полностью переназначаемые горячие клавиши с валидацией конфликтов;
- Локализация ru/en на лету (JSON-словари);
- Ключи командной строки: выбор базы/пространства при старте и консольное обслуживание БД — миграции схемы, снапшот, проверка целостности, создание новой базы — с кодами возврата для скриптов и автодеплоя; работают даже при запущенном приложении (см. [Ключи запуска](#ключи-запуска));
- Защита от повторного запуска (один экземпляр приложения);
- FastMM5 и отчёт об утечках памяти в Debug-сборке.

## Архитектура и структура репозитория

Приложение построено послойно: формы не знают о базе данных напрямую — доступ идёт через сервисы и интерфейсы, зависимости собираются в `Core.AppContext` при старте.

```
SSHSnippetsKeeper/
├── Automation/            # Автоматизация ввода: WindowHelper, WindowMonitor, ProcessProfile
├── Assets/
│   ├── ExeData/           # Ресурсы рядом с exe: настройки, локализация, автодополнение
│   │   └── Python/        # (не в git) встраиваемый Python 3.13 для локального AI
│   └── Images/            # Иконки и графика
├── Common/                # Общие модули: константы, хелперы, локализация, настройки
├── Core/
│   ├── Entities/          # Доменные модели: Snippet, Category, Tag, User
│   ├── Services/          # Бизнес-логика: SnippetService, HotkeyService, PasswordService...
│   ├── Interfaces/…       # Контракты (Core.Interfaces.*)
│   └── …                  # AppContext, LocalAIService, Markdown-импорт/экспорт
├── Database/
│   ├── Migrations/          # Версионные миграции схемы V001–V012 (RCDATA-ресурсы)
│   ├── Schema/              # Baseline-схема (v12) и seed-данные (компилируются в ресурс)
│   └── Tests/               # SQL-скрипты проверки данных
├── Data/
│   ├── Repositories/                  # Репозитории поверх FireDAC
│   ├── Data.Database.pas              # TDataModule: подключение, PRAGMA, схема
│   └── Data.Database.Migrations.pas   # Раннер версионных миграций и консольные команды
├── MacroEngine/           # Разбор и выполнение макросов, типы ввода
├── Resources/             # Ресурсы приложения (иконка)
├── Tests/                 # DUnitX-тесты (консольный раннер)
├── ThirdParty/            # Bcrypt, JSONSerializer, ArrayHelper
├── vendor/                # Вендоренные библиотеки: SynEdit, HtmlViewer, FastMM5, python4delphi
└── UI/
    ├── Controls/          # Кастомные контролы (адаптер темы SynEdit и др.)
    ├── Controllers/       # Контроллеры: поиск, дерево категорий, синхронизация, запуск сниппетов и цепочек
    ├── Forms/             # VCL-формы
    ├── Helpers/           # UI-хелперы
    ├── Services/          # UI-сервисы: состояние приложения, AI-сервис, сообщения
    └── ViewModels/        # Модели представления
```

Ключевые принципы:

- интерфейсы сервисов собраны в `Core/Core.Interfaces.*.pas`, реализации — в `Core/Services` и `UI/Services`;
- репозитории (`Data/Repositories`) инкапсулируют SQL; схема БД хранится отдельными `.sql`-файлами;
- именование юнитов — точечное: `Common.*`, `Core.*`, `Data.*`, `UI.Services.*`, `Tests.*`.

## Сборка из исходников

### Требования

- RAD Studio / Delphi 12 Athens (цель **Win64**, поддерживается и Win32);
- Внешних библиотек не требуется: SynEdit, HtmlViewer, FastMM5 и python4delphi вендорены в `vendor\`; DUnitX входит в поставку RAD Studio.

### Шаги

1. Клонируйте репозиторий:

   ```
   git clone https://github.com/iamtoizy/SSHSnippetsKeeper.git
   ```

2. Соберите проект в IDE (`SSHSnippetsKeeper.dproj`, цель **Win64**) или из командной строки — проверенная команда (из корня репозитория):

   ```
   cmd /c ""C:\Program Files (x86)\Embarcadero\Studio\23.0\Bin\rsvars.bat" && msbuild SSHSnippetsKeeper.dproj /t:Build /p:Config=Release /p:Platform=Win64 /nologo /v:m"
   ```

   Готовый exe — `Binary\Win64\Release\SSHSnippetsKeeper.exe` (Debug — `Binary\Win64\Debug`). Ресурсы SQL-схемы, миграций и версии компилируются автоматически (`RcCompile` в `.dproj`). Debug-сборка включает FastMM5 с отчётом об утечках памяти, `FastMM_FullDebugMode.dll` попадает в папку вывода при сборке.

### Встраиваемый Python (опционально, для локального AI)

Основное приложение собирается и работает без Python. Локальная LLM требует:

1. Скачайте **Windows embeddable package** Python 3.13 с [python.org](https://www.python.org/downloads/windows/) — разрядность должна совпадать с разрядностью сборки приложения (для Win64 — 64-bit) — и распакуйте в `Assets\ExeData\Python\` (папка исключена из git через `.gitignore`);
2. Модуль `llama-cpp-python` устанавливается из интерфейса настроек AI (кнопка установки модуля), GGUF-модель указывается там же.

Без встроенного Python приложение попробует найти системный Python через реестр (Python4Delphi).

## Первый запуск

Приложение ищет файлы ресурсов в двух местах: сначала рядом с `.exe` (релизный сценарий), затем в `<корень репозитория>\Assets\ExeData\` (сценарий разработки). Если файл не найден, папка создаётся автоматически.

| Файл | Назначение |
|---|---|
| `settings.json` | Пользовательские настройки (создаётся из `settings.template.json`; в git не попадает) |
| `Translation\ui-texts.ru.json`, `ui-texts.en.json` | Локализация |
| `bash.autocomplete.json` | База автодополнения bash: команды и дерево подкоманд |
| `sqlite3mc_x64.dll` | Опционально: шифрование базы данных (см. [Шифрование базы данных](#шифрование-базы-данных)) |
| `Python\` | Встраиваемый Python (см. выше) |
| `Styles\` | VCL-стили интерфейса (.vsf); без них доступен только стандартный стиль Windows |

Стили интерфейса в репозиторий не входят (лицензия RAD Studio). Чтобы переключать темы в *Настройки → Общие*, положите `.vsf`-файлы (например, из `C:\Users\Public\Documents\Embarcadero\Studio\23.0\Styles\`) в папку `Styles` рядом с `.exe` (папки в git не попадают). Стиль применяется сразу и запоминается в `settings.json`; TSynEdit-редакторы перекрашиваются автоматически.

Порядок первого запуска:

1. Скопируйте `Assets\ExeData\settings.template.json` в `settings.json` (рядом с exe) и при необходимости заполните секцию `AllowedApplications` и пресеты AI;
2. Запустите приложение, создайте базу данных — **Ctrl+N** (схема накатывается автоматически из встроенного ресурса);
3. Откройте базу — **Ctrl+O**, закройте — **Ctrl+Q**.

## Ключи запуска

Префиксы `/`, `-` и `--` равнозначны, регистр не важен; значение можно передавать и через `=`: `-db=C:\base.sqlite`.

Ключи GUI:

| Ключ | Действие |
|---|---|
| `-db=<путь>` | Открыть указанную базу SQLite при старте |
| `-user=<имя>` | Выбрать пространство по имени (используется после `-db`) |
| `-nosync` | Отключить автоматическую синхронизацию с Markdown-хранилищем |
| `-minimized` | Запустить приложение свёрнутым |

Обслуживание БД (консольный режим):

| Команда | Действие |
|---|---|
| `-migrate -db=<файл>` | Накатить миграции схемы до текущей версии; перед первым шагом создаётся резервная копия БД |
| `-backup [путь] -db=<файл>` | Снапшот БД через `VACUUM INTO`; путь (папка или файл) указывается сразу после `-backup` или через `-backup=<файл>`; без пути копия создаётся рядом с БД и участвует в ротации (хранятся три последние) |
| `-checkdb -db=<файл>` | Проверка целостности: `integrity_check` + `foreign_key_check` |
| `-newdb <файл>` | Создать новую БД с базовой схемой (v12) и пользователем «Local User»; существующий файл не перезаписывается |
| `-version` | Версия приложения |
| `-help` | Справка по всем ключам |

Команды обслуживания выполняются до проверки «один экземпляр», поэтому работают и при запущенном GUI; GUI при этом не запускается и не активируется, процесс сразу завершается. Вывод виден в cmd/PowerShell; при запуске из Проводника он не показывается.

Примеры:

```
SSHSnippetsKeeper.exe -backup "D:\Backups\" -db="C:\Data\snippets.sqlite"
SSHSnippetsKeeper.exe -checkdb -db="C:\Data\snippets.sqlite"
```

Коды возврата команд обслуживания (для скриптов и автодеплоя): `0` — успех, `2` — схема БД создана более новой версией приложения, `3` — ошибка выполнения, `4` — файл БД не найден или не указан, `5` — проверка целостности выявила проблемы.

Реализация: разбор ключей — `Common/Common.CmdLine.pas`, консольные команды и раннер миграций — `Data/Data.Database.Migrations.pas`; миграции — `Database/Migrations/V*.sql` с гейтом по `PRAGMA user_version`. Тесты: `Tests/Tests.CmdLine.pas`, `Tests/Tests.DbMigrations.pas`.

## Синтаксис макросов

Макросы пишутся прямо в тексте сниппета в фигурных скобках. Нераспознанная конструкция остаётся обычным текстом.

| Макрос | Действие |
|---|---|
| `{SLEEP 500}` | Пауза 500 мс |
| `{ENTER}` | Нажатие Enter |
| `{SENDKEY X}` | Отправка символа X, имени клавиши (ENTER, TAB, F1-F12 и др.) или VK-кода |
| `{SENDKEY CTRL+K}` | Комбинации: CTRL/ALT/SHIFT + клавиша (например, `CTRL+C`, `ALT+F4`, `CTRL+SHIFT+T`) |
| `{CLEAR_LINE}` | Очистить текущую строку терминала: Ctrl+C, пауза, Ctrl+U |
| `{INPUT подсказка}` | Запрос ввода строки перед выполнением |
| `{INPUT [ТИП:значение] подсказка}` | Запрос ввода заданного типа со значением по умолчанию |
| `{DATETIME:ФОРМАТ}` | Текущие дата и время (маска FormatDateTime); без аргумента `yyyy-MM-dd HH:mm:ss` |
| `{UUID}` | Новый UUID в нижнем регистре |
| `{RANDOM:N}` | Случайная строка из N букв и цифр (по умолчанию 16) |
| `{COUNTER}` | Порядковый номер запуска сниппета (1, 2, 3...) |
| `{ENV:ИМЯ}` | Значение переменной окружения на момент запуска |
| `{CLIPBOARD}` | Текст из буфера обмена на момент запуска |
| `{KEYDELAY N}` | Пауза между символами (мс) для последующего текста |

Типы ввода: `STRING`, `NUMBER`, `HEX`, `FLOAT`, `PASSWORD`, `DATE`, `CONFIRM`, `SELECT`.

Для типа `SELECT` в значении через `|` перечисляются варианты: `{INPUT [SELECT:prod|stage|dev] Окружение}`. При запуске сниппета с несколькими `{INPUT}` все параметры собираются в одном окне; для `CONFIRM` - отдельный вопрос по ходу выполнения.

Пример сниппета — перезапуск nginx на указанном сервере:

```
ssh {INPUT [STRING:user@host] Адрес (user@host)}
{ENTER}
{SLEEP 800}
sudo systemctl restart nginx
{ENTER}
```

Перед выполнением приложение запросит адрес, подключится к выбранному окну терминала, наберёт команду посимвольно и подтвердит Enter. Разбор макросов кэшируется (до 5000 сниппетов).

## Поиск по сниппетам

Строка поиска в главном окне и в HUD быстрого поиска понимает простой язык запросов. Поиск нечувствителен к регистру. В полнотекстовом режиме (FTS5, триграммный индекс) обычные слова находят и части слов: запрос `List` найдёт `TList`; индекс покрывает название, код, комментарий и теги, результаты сортируются по релевантности.

| Токен | Действие |
|---|---|
| `слово` | Полнотекстовый поиск по названию, коду, комментарию и тегам; несколько слов подряд ищутся как фраза |
| `tag:nginx` | Имя тега содержит подстроку; несколько `tag:` - все условия должны выполняться одновременно |
| `cat:сеть` | Сниппет находится непосредственно в подходящей категории (вложенные категории не учитываются); несколько `cat:` - достаточно любой |
| `title:ssh` | Подстрока в названии; несколько `title:` - все должны совпасть |
| `comment:туннель` | Подстрока в комментарии; несколько `comment:` - все должны совпасть |
| `fav` | Только избранные сниппеты |
| `-слово` | Исключить сниппеты, содержащие слово в тексте (название, код; в FTS-режиме также комментарий и теги) |

Токены свободно комбинируются: `fav tag:docker title:logs -prod` - избранные сниппеты с подходящим тегом, `logs` в названии и без `prod`. Неизвестные префиксы (например, `foo:bar`) считаются обычными словами поиска. В режиме без FTS обычные слова и исключения ищутся подстрокой по названию и коду.

Разбор запроса: `Common/QueryLanguage.pas`, SQL-построитель: `Data/Repositories/SnippetRepository.pas` (`SearchAdvanced`), тесты: `Tests/Tests.QueryLanguage.pas`.

## Цепочки и массовые операции

**Цепочки** — именованные последовательности сниппетов, выполняемые по порядку в выбранное окно терминала (таблицы `snippet_chains` и `snippet_chain_steps`). Создание: ПКМ по узлу «Цепочки» в дереве → «Создать цепочку», либо ПКМ по сниппету → «Создать цепочку из сниппета». В редакторе шаги берутся из библиотеки всех пространств (двойной клик или «Добавить шаг»), порядок меняется перетаскиванием или Ctrl+↑/Ctrl+↓, Del убирает шаг, для каждого шага задаётся пауза в секундах. Запуск — двойной клик по цепочке или ПКМ; во время выполнения появляется панель с прогрессом, остановка — «Стоп» или Esc. Изменение и удаление — ПКМ по цепочке. Реализация: `Core/Services/ChainService.pas`, `UI/Controllers/ChainRunnerController.pas`, `UI/Forms/ChainEditorFormUI.pas`.

**Мультивыбор** — в списке сниппетов работают Ctrl/Shift-выделение, ПКМ по выделенному не сбрасывает его. Контекстное меню предлагает массовые операции:

- **Выполнить по порядку** (при двух и более выделенных) — диалог с изменением порядка (Ctrl+↑/Ctrl+↓, Del), затем пошаговый ввод, как у цепочки;
- **Экспортировать** — плоская выгрузка выделенных сниппетов в папку в формате Markdown-хранилища (по одному `.md`-файлу на сниппет);
- **Добавить тег...** — поиск по существующим или ввод нового имени; тег добавляется всем выделенным, дубликаты пропускаются;
- **Удалить тег...** — выбор одного или нескольких тегов выделенных сниппетов; выбранные теги снимаются у всех выделенных;
- **Переместить в категорию...** — дерево всех пространств и категорий; перенос возможен и между пространствами, избранное при этом сохраняется; по итогу — отчёт «перемещено/пропущено».

Реализация: `UI/Forms/SequenceOrderDialogUI.pas`, `UI/Forms/TagSelectDialogUI.pas`, `UI/Forms/CategorySelectDialogUI.pas`, `Core/Services/SnippetService.pas` (`MoveSnippet`).

## База данных

- Движок: SQLite через FireDAC, файл базы выбирает пользователь;
- Baseline — `Database/Schema/000_schema_init.sql` + seed-данные (`000_seed_data.sql`, `000_seed_data_full.sql`; проверка данных — `Database/Tests/verify_data.sql`); компилируется в ресурс и применяется при создании новой базы (**Ctrl+N** или ключ `/newdb`);
- Версионные миграции — `Database/Migrations/V*.sql` (идемпотентные, реестр ресурсов в `Migrations.rc`), раннер `Data/Data.Database.Migrations.pas` с гейтом по `PRAGMA user_version`: при открытии базы отстающая схема автоматически догоняет до текущей версии; перед первым шагом создаётся резервная копия файла (`VACUUM INTO`), хранятся три последние; каждая миграция — одна транзакция. Базу, созданную более новой версией приложения, открыть нельзя;
- Сущности: сниппеты, категории, теги, пользователи, история изменений, избранное, цепочки сниппетов; связи многие-ко-многим;
- После открытия базы применяются PRAGMA: `journal_mode=WAL`, `synchronous=NORMAL`, `foreign_keys=ON` и др.; при `synchronous=NORMAL` сбой питания может стоить последних зафиксированных транзакций — целостность базы сохраняется. При закрытии выполняется принудительный checkpoint WAL на диск;
- Консольные команды обслуживания (`/migrate`, `/backup`, `/checkdb`, `/newdb`) с кодами возврата — см. [Ключи запуска](#ключи-запуска).

### Шифрование базы данных

База может быть зашифрована движком [SQLite3 Multiple Ciphers](https://utelle.github.io/SQLite3MultipleCiphers/) (дефолтный шифр ChaCha20-Poly1305, ключ 32 байта, PBKDF2). Управление - *Настройки → Безопасность базы данных*: включение и выключение применяются к открытой базе сразу (перед конверсией файла создаётся резервная копия), режим ключа - DPAPI этой машины или парольная фраза (вывод ключа: PBKDF2-HMAC-SHA256, 600 000 итераций, соль 16 байт). Новая база создаётся сразу зашифрованной (DPAPI, свежий случайный ключ): приложение уведомляет, что ключ привязан к машине, а тип шифрования можно изменить в настройках.

Перенос базы на другую машину: экспортируйте ключ в JSON-файл (имя содержит дату и время, например `snippets-db-key-2026-11-13_13-05-00.json`; файл дополнительно шифруется своей парольной фразой) и импортируйте его на целевой машине. База в passphrase-режиме при открытии запрашивает парольную фразу (до трёх попыток, затем предлагается импорт ключа); в DPAPI-режиме база с другой машины сразу предлагает импорт ключа. Перед включением шифрования создаётся резервная копия в текущем (незашифрованном) виде - приложение показывает её путь и напоминает удалить копию после проверки зашифрованной базы; при включении и снятии шифрования база переоткрывается с новым состоянием в фоновом режиме с индикатором прогресса. После включения шифрования приложение сразу предлагает сохранить ключ в файл - без него зашифрованную базу не открыть на другой машине; позже это можно сделать кнопкой «Экспорт ключа».

Ключ каждой базы хранится в `settings.json` в её профиле (`DbProfiles`, запись привязана к нормализованному пути файла базы) под DPAPI-защитой - файл раскрывает ключи только на этой машине и под этим пользователем Windows. В passphrase-режиме хранением управляет комбо «Сохранение ключа»: «Сохранять ключ» закрепляет фактический ключ открытой базы в её профиле, «Не сохранять ключ» удаляет его (пароль будет запрашиваться при каждом открытии); в DPAPI-режиме ключ хранится всегда - без него базу не открыть. Кнопка «Профили баз...» показывает сохранённые ключи всех баз: оттуда можно удалить ключ базы, с которой снято шифрование, или запись о несуществующем файле. Кнопка «Справка» показывает сводку этих правил. Смена типа ключа на уже зашифрованной базе («Применить» с другим режимом) - полноценная конверсия с резервной копией под прежним ключом; если материал ключа не меняется (запомненная фраза → DPAPI), обновляются только настройки.

Флаг шифрования в настройках - один на приложение, поэтому при каждом открытии базы программа определяет фактическое состояние файла по заголовку и молча подводит интерфейс к реальности: незашифрованная база открывается без ключа, для зашифрованной используется ключ её профиля. Ключ и режим каждой базы привязаны к пути её файла, поэтому ключи разных баз не подменяют друг друга. Зашифрованная база без сохранённого ключа в passphrase-режиме даёт три попытки парольной фразы (ключ выводится по соли этой базы), затем предлагает импорт ключа; DPAPI-база без ключа или с чужой машины сразу предлагает импорт. Для баз, открытых до появления профилей, сохранённый глобальный ключ используется как наследие и автоматически копируется в профиль базы. «Применить» конвертирует файл при включении, выключении или смене типа ключа; если файл уже в требуемом состоянии - только актуализирует настройки.

Библиотека `sqlite3mc_x64.dll` не входит в репозиторий и в поставку: скачайте win-x64 сборку со страницы [релизов SQLite3 Multiple Ciphers](https://github.com/utelle/SQLite3MultipleCiphers/releases) и положите рядом с `SSHSnippetsKeeper.exe` (для тестов шифрования - также рядом с тестовым exe). Без библиотеки приложение продолжает работать с незашифрованными базами на встроенном движке SQLite; зашифрованную базу открыть нельзя - при открытии выводится сообщение об отсутствующей библиотеке, а управление шифрованием в настройках деактивируется.
